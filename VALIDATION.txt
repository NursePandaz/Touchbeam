A receiver-side callback is emitted only after the unbonded NFC-key channel
handshake authenticates successfully. The current receiver listener then bypasses
its file/batch acceptance dialog or notification and creates the same verified
private-storage sink used previously. Authorization covers one transfer (a single
file or complete batch); it is not persisted or shared with another session.

The sender's original Touch to beam preview still requires a tap to send. The
wire ACCEPT frames remain for protocol compatibility; they are automatic on this
verified path. Receipt, checksums, size limits, atomic batch commit, cancellation
and latest-complete-batch storage behavior are unchanged. Background readiness
must be enabled once; the receiver must remain unlocked when the offer arrives.
Stop in its notification or Cancel beam can still interrupt reception.

Classic/manual connections still ask for Accept. A public UUID match, selecting a
phone, or an unsuccessful NFC-key proof does not authorize automatic receipt.
The new route requires compatible Android 10+ BLE advertising/scanning, LE L2CAP
and NFC/HCE. Use 0.9 on BOTH phones for the complete no-Accept workflow. Older or
unsupported devices retain the Classic fallback and its existing prompts.

No phones or emulator were connected. Host tests use in-memory streams and Android
type substitutes; actual NFC, BLE radios, background lifecycle, notifications and
native UI remain unverified on hardware. The pair-free application encryption
protocol remains experimental and not independently security-audited.

Warnings retained: SDK 35 rather than newest (standalone only), scan flag ignored
below API 31, Back flag ignored below API 33, portrait/large-screen compatibility.
